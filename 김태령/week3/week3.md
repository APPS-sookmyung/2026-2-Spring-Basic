# Spring_Basic Week3,4,5

## 1. 회원 관리 예제

### 웹 애플리케이션 계층 구조

| 구성 요소 | 역할 |
|---|---|
| Controller | 웹 요청 처리 |
| Service | 핵심 비즈니스 로직 처리 |
| Repository | 데이터 저장 및 조회 |
| Domain | 회원, 주문 등 비즈니스 객체 |

전체 흐름: `Controller → Service → Repository → DB`

### 회원 관리 기능

- 회원 데이터: ID, 이름
- 주요 기능: 회원 등록, 회원 조회
- 저장소가 정해지지 않아 인터페이스로 리포지토리를 설계하고, 초기에는 메모리 저장소를 사용

### 주요 개념

- **Member**: 회원 ID와 이름을 갖는 도메인 객체
- **MemberRepository**: 회원 저장 및 조회 기능을 정의하는 인터페이스
- **MemoryMemberRepository**: `HashMap`을 이용한 메모리 저장소 구현체
- **Optional**: 조회 결과가 없을 수도 있음을 표현
- **sequence**: 회원 ID를 순서대로 생성하기 위한 값

### 테스트

- JUnit을 사용해 기능을 검증
- `@Test`: 테스트 메서드 지정
- `@BeforeEach`: 각 테스트 실행 전에 호출됨. 항상 새로운 객체 생성 및 의존관계 새로 맺어줌
- `@AfterEach`: 각 테스트가 종료될 때마다 이 기능을 실행. 메모리 DB에 저장된 데이터를 삭제
- 테스트는 서로 독립적이어야 하며, 이전 테스트 데이터가 남지 않도록 저장소를 초기화 필요
- **Given-When-Then**: 준비 → 실행 → 결과 검증

## 2. 스프링 빈과 의존관계

### DI(Dependency Injection, 의존성 주입)

객체가 필요로 하는 의존 객체를 외부에서 전달받는 것.

- 생성자 주입을 통해 객체 간 의존관계를 연결
- 서비스가 리포지토리를 직접 생성하지 않고 생성자를 통해 전달받도록 변경
- 생성자 주입은 의존관계가 명확하고, 실행 중 변경될 일이 적어 권장됨

### 스프링 빈(Spring Bean)

스프링 컨테이너가 생성하고 관리하는 객체.

- `@Autowired`: 스프링 컨테이너에서 필요한 빈을 찾아 주입
- 생성자가 하나라면 `@Autowired` 생략 가능
- 스프링이 관리하지 않고 직접 생성한 객체에는 `@Autowired`가 자동으로 동작하지 않음

### 스프링 빈 등록 방법

**1) 컴포넌트 스캔**

애노테이션을 이용해 스프링 빈을 자동 등록하는 방식.

| 애노테이션 | 역할 |
|---|---|
| `@Controller` | 컨트롤러 등록 |
| `@Service` | 서비스 등록 |
| `@Repository` | 리포지토리 등록 |
| `@Component` | 컴포넌트 등록 |
| `@Autowired` | 의존 객체 주입 |

`@Controller`, `@Service`, `@Repository`는 `@Component`를 포함하므로 컴포넌트 스캔을 통해 자동 등록됨.

**2) 자바 코드로 직접 등록**

- `@Configuration`: 설정 클래스 지정
- `@Bean`: 메서드가 반환하는 객체를 스프링 빈으로 등록
- 구현 클래스를 상황에 따라 변경해야 할 때 유용

### 싱글톤(Singleton)

스프링 빈은 기본적으로 싱글톤으로 등록됨.

- 스프링 컨테이너에 하나의 인스턴스만 등록
- 같은 빈을 요청하면 동일한 객체를 공유
- 특별한 경우가 아니면 대부분 싱글톤 사용
