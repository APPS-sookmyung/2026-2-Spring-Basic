## 자바로 개발하면서 불편했던 점
자바 -> 객체지향언어 -> 객체를 직접 생성하고 관리해야함 -> 불편, 복잡
- 어디서 생성할지
- 언제 생성할지
- 어떻게 연결할지 (객체 간)
- 언제까지 사용할지

=> 스프링은 이러한 불편함을 해결하기 위해 객체의 생성과 관리, 객체 간의 연결을 대신 담당.

## 스프링의 주요 원리
1. IoC
- Inversion of Control 제어의 역전 : 프로그램의 흐름을 제어하는 주체가 정반대로 바뀌었다.
- inverse : 정반대로 뒤집힌다. (상황이 180도 바뀐다) 
- 뭐가? 제어 "프로그램 흐름 = 객체의 흐름"
- = 객체의 제어권을 정반대로 뒤집는다. 
- 원래 제어권(객체 생성, 사용,...라이프 사이클)은 개발자가 가지고 있었는데, 스프링은 제어권을 가지게 되었고, 개발자는 제어권을 뺐김. (역전, 즉, 상황이 180도 바뀜)

2. 컨테이너
-> 스프링이 객체를 생성하고 관리해야함.
객체가 너무 흩뿌려져 있으면 관리하기 어렵 .
-> 통안에 박스에 넣어두고 객체들 관리.
-> "스프링/IoC/DI 컨테이너"

3. 스프링 빈
스프링은 자신의 컨테이너 안에 있는 객체들을 스프링 빈이라고 부름.

4. DI
- Dependency Injection 의존성 주입
- 의존한다 = 사용한다, 의존성 = 사용할(하는) 것 = 객체
- 개발자: 주입 당한다(받는다), 스피링 : 주입해준다.
- => 내가(개발자가) 필요하다고 하면 객체를 스프링한테 주입받는 것.
cf. 객체를 사용한다? 객체를 생성해서, 메소드/필드를 호출, 접근한다.

=> IoC를 구현하기 위해 DI가 필요하다.
