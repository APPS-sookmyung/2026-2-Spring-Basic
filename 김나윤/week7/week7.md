## Spring MVC란
#### 클래스 구조 ( = 역할 부여 )
1. View 화면
- 스프링에서 사실 화면 만들 수 있음.
- 하지만, 이제는 역할을 나눠서 개발하기 때문에 프엔이 화면개발 담당
- 여기서 안함..

2. Controller
- View(사용자)와 Model의 중간 매개체 역할

3. Model
- 데이터 연산, 로직.
- 즉, DB랑 소통과 로직 둘 다 해야함. -> 해야할 역할이 많음 -> 역할 나눔.
- DB소통 : Repository, 로직: Service(상세역할)

cf. view, controller.. 는 특별한 클래스다. X -> 아무 클래스 놓고 이 클래스는 컨트롤러 역할을 할 것이다 하면 컨트롤러 가 되는 것임. 즉, 클래스 구조는 역할을 부여하는 것.

-> 만들 프로그램에 적용
-> 상품 조회랑 등록을 요청하면 컨트롤러가 받아줌. 

## 어노테이션
객체를 주입해주는 것은 스프링 담당임 -> 이 클래스를 스프링한테 맡겨야함.
 ->스프링한테 "이거 객체로 잘 부탁한다" 라고 말해줘야함. -> How? -> 어노테이션으로

역할 : 스프링에게 알려줌.
"아래 세 친구에게 알려주기"
1. 컴파일러에게 -> 아래 메소드 오버라이드 하고 싶은데, 문법 체크좀 해줘.
- 정작 일을 하는 건 컴파일러. 
- 어노테이션은 알려주기만 함
- ex. @Override

2. 빌드도구에게
- ex. 코드 생성할 때 . @Getter

3. 프레임워크에게
- ex. @스프링아..나 아래 클래스를 스프링빈으로 (객체로) 니가 좀 관리해줘..
